Client SDK that runs in an Agent's process.

[`BaseAgent`](/api/agent-base#agentconnect-agent-base-baseagent) is the usual entry: subclass it, set a `profile`, implement
`handle`, then `join` a started [`Team`](/api/team-runtime#agentconnect-team-runtime-team) or a Runtime URL. [`Context`](/api/agent-context#agentconnect-agent-context-context) is
passed into `handle` with verified delivery facts and verbs to `ask`,
`tell`, `find`, and `defer`. [`Session`](/api/agent-session#agentconnect-agent-session-session) is the connection [`BaseAgent`](/api/agent-base#agentconnect-agent-base-baseagent)
owns after join; construct it only when you need the transport yourself.

[`TeamTools`](/api/agent-tools#agentconnect-agent-tools-teamtools) binds the six coordination tools (`find`, `ask`, `tell`,
`get_result`, `get_history`, `get_profiles`) to this Session for
frameworks that do not speak MCP. Connecting a harness is adding the
Team MCP URL there instead. [`Tool`](/api/agent-tools#agentconnect-agent-tools-tool) describes one extra callable.

Identity JSON helpers live in [`agentconnect.agent.identity`](/api/agent-identity). Persist a
key with `identity_path` so a restart keeps the same DID.

A request (`ask`) opens a Ticket and expects a reply. A notice (`tell`)
does not. `collect="wait"` bounds that one call and may still return an
open Ticket; `collect="ticket"` returns immediately. Ending a wait does
not cancel accepted work. Collect later with `get_result`. Close a
Session with `leave` before stopping the Team. A complete embedded
request is on the [`agentconnect`](/api-reference) package overview.
