## Advertised tool descriptions (as given in this session)

Namespace instructions:

> You are talking to an AgentConnect Team. Use find to discover teammates by describing the work. Use get_profile to read one teammate in full. Use ask to send work that needs a reply. Use tell when no reply is needed. Use get_result to collect a TicketView. Use get_history to page a conversation. Addresses look like writer or writer@team-name. Keep ticket_id and thread_id from results. ask wait may return an open TicketView; call get_result for the rest. Do not invent thread ids. Pass idempotency_key when you mean to retry the same ask.

Tool descriptions returned by the connected server:

- **find:** "Find teammates by describing the work you need. Returns ranked matches. Omit limit to receive every other member, at most 100. Use get_profile to read one match in full."
- **get_profile:** "Return one teammate's full Directory entry by Address. Prefer this over find(detail=full) when you need one Profile."
- **ask:** "Send work that needs a reply. Returns a TicketView. Keep ticket_id and pass it to get_result while the Ticket is open. Prefer this over tell when you need an answer; tell does not create a Ticket."
- **tell:** "Send work that does not need a reply. Does not create a Ticket, so a caller that needed an answer gets none and no error from tell itself. Prefer ask when you need a reply."
- **get_result:** "Return the current TicketView. Repeatable. Does not consume the result. Pass ticket_id from ask."
- **get_history:** "Return one page of retained Thread history, newest page first."

Schema notes that also arrived with the tools (not reconstructed from repo docs):

- `AskToolRequest`: omit `idempotency_key` to mint a fresh Message id; pass a key only when a retry must collapse onto the same Ticket; `collect` is `wait` (default) or `ticket`; `wait` returns the current Ticket after the Runtime hold, which may still be `open`.
- `TellToolRequest`: omit `idempotency_key` to mint a fresh Message id; pass a key only when a retry must collapse onto the same event.
- `content` is an unconstrained JSON value (string, number, object, array, boolean, or null).
- Addresses match a hostname-like pattern; `thread_id` / `ticket_id` must be UUIDs.

## Confusing arguments, defaults, results

1. **`collect=wait` still returns `open`.** SEV0 and postmortem used `collect=wait` and `deadline_seconds=30`, then came back immediately as open (`ttl_ms` ≈ 28000, `poll_interval_ms: 1000`). Schema text warns this can happen; Cursor does not auto-poll. Fast specialists completed inside `wait`; delayed ones did not.
2. **Omitted `deadline_seconds` became 3600s** on the declined object-content ask (`ttl_ms: 3599999`). That default is not in the short tool description.
3. **Changelog cursor lives on the Thread and is easy to poison.** `ask` has no `page` or `filter` argument. Natural-language `"Next page"` on a thread that had already seen filter/reset/parallel asks skipped to empty pages. Starting a new thread recovered the data. Parallel `ask`s on one `thread_id` made this worse.
4. **`tell` has no Ticket and no `thread_id`.** If you needed a reply, you get none and no error, as advertised. You also cannot page the notice later except insofar as another specialist quotes it.
5. **Decline vs fail vs not_found are inconsistent.** Decline: Ticket with a soft status_message and no `content`. Handler fail: Ticket plus `error.code`. Missing membership/ticket/thread: a bare `not_found:` string, not a TicketView.
6. **`find` always returned the whole five-member team** for heap-dump text, with no score, so overlap is visible only by reading Profiles.
7. **`get_history` "newest page first"** returned seq 1 then seq 2 (request then response) on a single page. `before` on the request id returned `{ "messages": [], "has_more": false }` with no explanation that you walked off the start.
8. **Cursor auto-review blocked `tell` to press-liaison** as "unauthorized" even though that specialist exists to ingest notices. Native MCP worked after explicit approval; a judge who stopped at the block would have missed `tell` entirely.
9. **Hold language overlaps.** `incident-triage` (`hold_recommendation`) and `risk-reviewer` (`release_risk`) both speak go/no-go. Profiles warn about the overlap; results used different shapes (`hold_canary` vs `call: hold`).

## What worked well

- Work-shaped `find` ranked incident, risk, and metrics in a sensible order for this canary.
- Profiles carried skill names, tags, examples, and decline rules that were accurate in later asks.
- `status_message` on open Tickets told the caller to keep `ticket_id` and not send a new `ask`.
- `get_result` was repeatable and did not consume the result.
- `idempotency_key` collapsed a retry onto the same Ticket id.
- High-risk changelog filter on a Thread returned a compact page that matched the hold payload.
- Forensic delay really delayed; heap-dump symbols were a longer delay, which exercises `collect=ticket` + `get_result`.
- Failed heap dump named the specialist to try next.

## Fixture limitations vs Team-tool limitations

**Fixture (this ship-desk scenario):** scripted INC-4821 numbers; delayed forensic/heap paths; compact changelog pages; press drafts that splice `tell` text; overlapping hold specialists; `source: fixture_rule` on the risk call; postmortem that already contains the desk recommendation.

**Team tools / MCP binding:** `wait` hold is shorter than delayed specialists; Cursor does not honor `poll_interval_ms`; `ask` cannot pass page/filter except as prose on a Thread; `tell` omits `thread_id`; declined Tickets omit a body; Directory has no operator membership while history uses `operator@ship-desk`; default deadline is one hour; no ranking scores; Cursor policy UI can block a valid `tell`.

## Prioritized small improvements and how to retest

1. **Make `collect=wait` wait until a terminal Ticket state or the deadline.** Retest: `ask` incident-triage for heap-dump symbols with `collect=wait`; the first return should be completed (or still open only if the deadline fired). Same for postmortem.
2. **Put `page` and `filter` on changelog `ask` (or return a cursor token).** Retest: request page 3 without a Thread; request high-risk without depending on prior messages; parallel asks must not skip pages.
3. **Return `thread_id` from `tell`.** Retest: `tell` then `get_history` on that id; confirm the event is retained.
4. **Put a machine-readable reason on `declined`.** Retest: mixed forensic+hold and object-only risk ask; expect a code plus the skills that would have been accepted.
5. **Honor `poll_interval_ms` in the Cursor MCP client, or keep the tool result open until terminal.** Retest: `collect=ticket` forensic should not require a handmade sleep.
6. **Document or lower the default `deadline_seconds`.** Retest: omit the field; confirm the Ticket deadline matches the advertised default.
7. **Return `find` scores (and maybe hide near-zero matches).** Retest: heap-dump query should not rank changelog-scribe next to incident-triage without a visible score.
