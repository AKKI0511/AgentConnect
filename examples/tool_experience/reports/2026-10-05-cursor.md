## Confusing arguments, defaults, results, errors

- **`find` ranks everyone** for `legal contract drafting and payroll tax filing` (same five payments cards). Catalog says ranked cards are not proof of suitability and you may conclude nobody fits — that warning is doing real work. There is no empty-match signal.
- **`press-liaison` defaulted** on `Draft a legal hold contract for payroll tax filing` — completed with the stock checkout status. Profile said other work is declined. Changelog actually declined a similar ask. Mixed signal across specialists.
- **Declined TicketView** has `status_message` but **no `content` reason**. History on that Thread also lacks a response Message. You cannot tell *why* from the saved result.
- **`since` / `from` → `after`** in `constraint`. The filter is applied, but the echoed token is not the word you sent. `after 14:18` **included** the 14:18 event; `before 14:18` excluded it.
- **`collect=wait` default still returns open** for nested/slow work. Easy to misread as failure if you ignore `state` and the status_message.
- **`deadline_seconds` vs wait:** 1–2s on delayed forensic/postmortem expires the **work**. Open views still show a `deadline` even when you omitted `deadline_seconds` (Runtime work lifetime, here about an hour).
- **TellView is only `status: accepted`.** No id to poll, no Thread to continue, no echo of content.
- **HistoryView omits `thread_id`.** Pagination is “same Thread” only if you remember it.
- **`get_profile` address description** repeats “Prefer this when find cards overlap,” which is tool guidance, not an Address rule.
- **JSON `content` vs string:** metrics accepted `{"release":"2.4.1","service":"payments-api","task":"slo_snapshot"}` and still returned the full SLO snapshot. Convenient, but the specialist ignored unused keys rather than erroring.
- **Idempotency ticket ids** for the SLO retry looked UUID-like but not the same shape as first-seen random ids (deterministic from the key). Replay is clear; first-time callers may not expect a stable id.

## What worked well

- Compact find cards vs full Profile: overlap was obvious; `get_profile` description text named delayed forensics, filter reset, valid zero, and mixed-work decline.
- Open TicketView instructions (`keep ticket_id`, do not send another `ask`) matched nested hold and delayed forensic.
- `get_result` is repeatable and does not consume; completed forensic remained completed after its 12s deadline.
- Idempotency conflict text is readable and actionable.
- Timeline and changelog **echo constraints** (`constraint`, `filter`, `page`) so you do not have to assume follow-up applied.
- Empty list and zero are real JSON, not omitted fields.
- Forbidden / not_found / field-required errors are short and usable.
- Bare-string `content` is enough; no Message envelope required on `ask`/`tell`.

## Prioritized small improvements and how to retest

1. **Declined TicketView should carry a short reason in `content` (or a response Message in history).** Retest: ask changelog for a refund policy; expect a reason without `get_history` archaeology.
2. **Out-of-skill specialists should decline, not return a default document.** Retest: ask `press-liaison` for a legal contract; expect `declined`, not the checkout status.
3. **TellView should include `thread_id` and a message id if unthreaded notices are meant to be continued or audited.** Retest: `tell` then continue that id; today you cannot.
4. **HistoryView should echo `thread_id`.** Retest: page with `limit=2` and confirm the view names the Thread.
5. **`find` should be allowed to return no matches (or an explicit nobody-fits payload) for unrelated work.** Retest: legal/payroll query.
6. **Document or serialize tell-before-ask:** a later `ask` in the same parallel batch can miss a notice. Retest: sequential vs parallel legal-hold + status draft.
