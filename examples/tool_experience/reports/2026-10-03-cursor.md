## Confusing arguments, defaults, results

1. **`collect` default `wait` still returns `open`.** The tool
   description says so, but the first SEV0 wait looked like a stall. The
   useful next call is `get_result`, not a retry `ask`.
2. **`poll_interval_ms=1000` on open Tickets** does not match the
   forensic delay I actually saw. It is a hint, not the work duration.
3. **Default work lifetime is one hour** (`ttl_ms` ≈ 3_600_000 on
   completed asks). `deadline_seconds` minimum is 1; I needed a short
   deadline on purpose to expire heap-dump work.
4. **Declined Tickets hide why.** Failed Tickets carry `error.message`.
   Declined Tickets only say `"The recipient declined."`
5. **`find` summary vs `get_profile`.** Overlap between incident-triage
   and risk-reviewer is in `description`. Summary cards are not enough
   to choose.
6. **`get_history` cursor is unlabeled.** Argument name `before`; the
   body never repeats it. Newest page is the latest messages, ordered
   oldest-to-newest inside the page.
7. **TicketView `content` is only on completed.** Open views have
   `poll_interval_ms`; failed/expired have `error`; declined has
   neither.

discovery; delays of a few seconds; memory store; operator loopback.

**Team tools:** duplicate-looking error wrapping, `-32602` vs prefixed

This run does not test member Session recovery, Bearer expiry, Redis
durability, or process crash.

## Prioritized small improvements

1. **Return Runtime errors as structured MCP errors** (`not_found`,
   `forbidden`, `id_conflict`) instead of
   `Error executing tool ask: {json}`. Keep `-32602` for missing
   fields, or use a distinct auth/validation code if those diverge.
   Retest: unknown recipient, off-Thread `tell`, omitted `recipient`.
2. **Put `thread_id` and the `before` cursor on the history page
   body.** Retest: changelog Thread, `limit=3`, walk older pages
   without guessing `messages[0].id`.
3. **Surface a decline reason** on declined TicketViews. Retest:
   payroll (or any declined ask) and confirm the caller can see why.
4. **Include `description` (or a one-line overlap hint) on `find`
   summary cards**, or say in the tool text that `get_profile` is
   required when matches share tags. Retest: go/no-go query where
   incident-triage and risk-reviewer both appear.
5. **Keep `ttl_ms` from implying expiry on its own.** Expired heap dump
   correctly had `ttl_ms=0` with `state=expired`. Still branch on
   `state`. Retest: `get_result` on expired vs completed Tickets.

Do not claim token savings. This harness rendered structured JSON; I
did not measure tokens or a duplicate text block.
