## Advertised tool descriptions (loaded)

Namespace text, quoted as returned:

> You are talking to an AgentConnect Team. Use find to discover teammates by describing the work. Use get_profile to read one teammate in full. Use ask to send work that needs a reply. Use tell when no reply is needed. Use get_result to collect a TicketView. Use get_history to page a conversation. Addresses look like writer or writer@team-name. Keep ticket_id and thread_id from results. ask wait may return an open TicketView; call get_result for the rest. Pass idempotency_key when you mean to retry the same ask.

Per-tool descriptions, quoted as returned:

- `find`: "Find teammates by describing the work you need. Returns ranked candidates, not a guarantee of suitability. Compact cards omit description; call get_profile when matches overlap. Reuse what you already read. You may conclude nobody fits. Omit limit to receive every other member, at most 100."
- `get_profile`: "Return one teammate's full Directory entry by Address. Prefer this over find(detail=full) when you need one Profile, especially when summary cards overlap."
- `ask`: "Send work that needs a reply. Returns a TicketView: the saved result of that request. If state is open, keep ticket_id and call get_result; do not send another ask to collect. collect=wait bounds this call only and may still return open. deadline_seconds cuts off work, not the wait. Omit thread_id to start a conversation. Continue a returned thread_id only with the same recipient. Prefer this over tell when you need an answer."
- `tell`: "Send work that does not need a reply. Does not create a Ticket, so a caller that needed an answer gets none and no error from tell itself. Prefer ask when you need a reply. Omit thread_id for an unthreaded notice. Continue a returned thread_id only with a current participant."
- `get_result`: "Return the current TicketView (saved request result). Repeatable. Does not consume the result. Pass ticket_id from ask. Branch on state. Open means keep waiting with this ticket_id; ttl_ms is not an ETA and not proof of state. A completed Ticket stays completed after its original deadline while retained."
- `get_history`: "Return one page of retained Thread history. The newest page is first; messages inside a page are oldest-to-newest. When has_more is true, pass next_before as before. Stop when has_more is false."

## Confusing arguments, defaults, results, errors

- `deadline_seconds` cuts off work. `collect` / `wait` bounds the call. Mixing them is the easiest operator mistake. The heap-dump 1s expiry proved the distinction. The tool text is correct; it is still easy to treat `deadline_seconds` as how long `ask` blocks.
- Default `collect: wait` can still return `open`. That is documented and still surprising the first time a hold or forensic `ask` "finishes" without `content`.
- `ttl_ms` is not an ETA. Open forensic tickets showed ~1 hour TTL while `poll_interval_ms` was 1000. The description warns about this; the numbers still look like a progress bar.
- Compact `find` cards omit `description`. Five overlapping payments specialists look interchangeable until `get_profile`. Skill names help (`hold_recommendation` vs `release_risk` vs `slo_snapshot`) but the cards do not say that mixed forensic+hold is declined, or that heap dumps fail on metrics.
- A metrics `ask` that names both SLO fields and additional canary percent can return only `{ "additional_canary_percent": 0 }`. That looks like a valid zero and hides the SLO breach if you stop there.
- Declined Tickets omit `content`. You have to read `state` and `status_message`.
- `tell` on another Thread is `forbidden` with a clear line. `ask` with a foreign `thread_id` would likely fail the same way; I recovered via unthreaded `tell`.
- press-liaison notice state is Team-global, not Thread-local. A later `ask` on a new Thread still incorporated earlier unthreaded notices. That is convenient and easy to miss if you expected isolation.
- `find` "omit limit to receive every other member" still returned the same five people. Fine for this Team; it does not feel like a search when every query is a permutation of the roster.
- History paging is correct and slightly awkward: newest page first, oldest-to-newest inside the page, cursor is `next_before`.

Selected error strings worth keeping:

- `not_found: Recipient Membership was not found`
- `forbidden: Message is outside this Thread's participant set`
- `MCP error -32602: content Field required`
- `id_conflict: The same idempotency_key was used with different arguments. …`

## Fixture limitations versus Team-tool limitations

Fixture:

- Five specialists, one incident, canned SLO and changelog rows.
- incident-triage ignores a time-window constraint on an existing Thread.
- metrics mixed-skill dispatch can drop SLO fields.
- press-liaison keyword handling for prepare versus confirmed rollback.
- Artificial delay on forensic / heap-dump / nested hold.
- `source: "fixture_rule"` on the risk-reviewer hold call.

Team tools:

- Operator is not a member Session; no mailbox to read.
- `ask` vs `tell`, Ticket vs notice, Thread participant lock.
- `collect=wait` may return `open`; collect by `ticket_id`.
- Idempotency `id_conflict`.
- History pagination shape.
- Validation errors (`content` required) versus domain errors (`not_found`, `forbidden`, `deadline_exceeded`).

Do not treat the ignored timeline constraint as a Team-history bug. `get_history` on that Thread would show the constraint text; the specialist result did not honor it.

## Prioritized small improvements (and how to retest)

1. **Do not silently shrink mixed metrics answers.** If one `ask` matches `canary_percent` and `slo_snapshot`, either return both or decline. Retest: one string that names p99, 5xx, error budget, and additional canary percent; expect the full SLO object or `declined`, not `{ "additional_canary_percent": 0 }` alone.
2. **Put a declined reason in `content`.** Status text is easy to miss next to a missing body. Retest: mixed forensic+hold and changelog hold/ship; expect a short reason payload.
3. **Keep compact cards from hiding disqualifiers.** A one-line "declines mixed forensic+hold; heap dumps fail on metrics" would have saved a round. Retest: `find` summary then `ask` mixed work without `get_profile`.
4. **Make `open` after `wait` harder to misread.** The status_message is already good. A required `content: null` plus `next: "get_result"` field would help callers who only parse `content`. Retest: hold recommendation and heap-dump notes with default `collect`.
5. **If conversation constraints are not applied, say so.** Timeline follow-ups returned the same document. Either honor "after 14:18" or reply that the timeline skill does not filter. Retest: the two follow-ups on Thread `17d5e5ae-…`.

## Untested cases and connection limits

Not tested here:

- `find` with an empty or whitespace `query` (schema forbids it).
- `get_history` as a non-participant.
- A well-formed unused `thread_id` that starts a conversation.
- `deadline_seconds` inherited from a parent request.
- Legal-hold wording ("will not expand") as its own notice, separate from prepare/confirm.
- `collect: wait` hitting a Runtime wait-hold limit that is shorter than work completion, then collecting later (I saw `open` from nested/slow work, not from a wait-hold budget).
- Cross-Team qualified addresses other than `@ship-desk`.
- `tell` with `idempotency_key`.

Connection: native Team MCP was connected and `namespaceStatus` was `ready`. Results rendered as JSON objects in the tool payload. No token counts, no latency histogram, no raw HTTP trace. Character length of the postmortem `notes` string was not measured beyond "much larger than other TicketViews."
