# AgentConnect repository context

AgentConnect is a runtime for Teams of independent AI agents. Each agent can use its own harness, tools, and memory. The Runtime provides discovery, messaging, and work tracking; it is not a wire standard.

This file describes the codebase and its constraints. There is no required editor, agent harness, or sequence of development steps.

## Code map

| Package | Responsibility |
| --- | --- |
| `agentconnect.core` | Public data models and schema projection |
| `agentconnect.agent` | Client SDK and handler context |
| `agentconnect.team` | Team Runtime, directory, mailboxes, tickets, and stores |
| `agentconnect.transport` | Client Session transports |
| `agentconnect.mcp` | Team MCP server |
| `agentconnect.cli` | Command-line entry point |
| `agentconnect.config` | Team configuration |
| `agentconnect.prebuilt` | Optional agent helpers and integrations |
| `agentconnect.index` | Optional published-directory Index |

Tests mirror these packages under `tests/`. Runnable examples are independent uv projects under `examples/`. Website sources and API generation live in `docs/`.

## Contracts and boundaries

- `spec/` describes the public contract. `spec/schema/schema.ts` owns public structure; `agentconnect/core/` is its Python projection. Public field changes affect both.
- Public Python models are frozen Pydantic models with matching field names, rejected extra fields, and discriminated tagged unions. Schema round-trip tests cover that correspondence.
- Validation happens at transport boundaries. Trusted internal construction avoids repeated validation. Model-facing tools return JSON.
- `core` imports no sibling packages. `agent` and `team` do not import each other; neither do `agent` and `mcp`. Those packages do not depend on `prebuilt`. Import tests cover these boundaries.
- Optional integrations stay behind extras and lazy imports. Core installation works without model providers or server packages. Public annotations and `py.typed` support SDK consumers.
- Team, Runtime, Membership, Session, Message, Delivery, Ticket, Thread, Address, and Skill have distinct meanings in the public contract.

## Generated content

`spec/schema/schema.json` is generated from `schema.ts`. Every RST file in `docs/source/api/`, including `index.rst`, is generated by `docs/generate_docs.py`. API templates live in `docs/apidoc-templates/`; API descriptions come from source docstrings. Manual changes to generated files are overwritten.

Website pages are self-contained. The root `CHANGELOG.md` is the canonical release history and is included through MyST; other repository references use links.

## Useful commands

uv manages the library environment, standalone tools, and example projects. `uv sync` installs the default development group; extras add integrations. The Makefile offers six optional shortcuts: check, format, test, perf, docs, and docs-preview.

When you add or change dependencies, extras, or dependency groups in any `pyproject.toml`, refresh every lockfile CI checks and commit those `uv.lock` files in the same revision. Do not push a dependency change without the matching locks. CI runs `uv lock --check` on the library and on `examples/quickstart` and `examples/recipes`.

```bash
uv lock
uv lock --directory examples/quickstart
uv lock --directory examples/recipes
uv lock --check
uv lock --check --directory examples/quickstart
uv lock --check --directory examples/recipes
uv sync --extra serve --extra cli --extra index --extra openai --extra redis
```

```bash
uv run --extra serve --extra cli --extra index --extra openai --extra redis pytest tests/agent/test_session.py -q
uv run --extra serve --extra cli --extra index --extra openai --extra redis pytest tests/ -q
uv run --group benchmark --extra serve --extra embeddings --extra redis pytest -q --benchmark-warmup=off benchmarks/runtime/test_phases.py
uvx ruff@latest check agentconnect tests examples benchmarks docs/generate_docs.py
uvx ruff@latest format --check agentconnect tests examples benchmarks docs/generate_docs.py
```

Redis tests use ``REDIS_URL`` (local default ``redis://127.0.0.1:6380/15``). They skip when Redis is unreachable unless ``CI`` or ``AGENTCONNECT_REQUIRE_REDIS=1`` is set, in which case missing Redis fails. The default suite is correctness plus real Redis. Runtime discovery benchmarks live under ``benchmarks/runtime/`` and run as sequential pytest groups (``make perf``, FastEmbed required when ``AGENTCONNECT_REQUIRE_NEURAL=1``). Do not collect them from ordinary CI.

Schema generation and freshness:

```bash
npm --prefix spec/schema ci
npm --prefix spec/schema run generate
npm --prefix spec/schema run check
```

Website and API preview:

```bash
uv run --group docs --extra serve --extra cli python docs/generate_docs.py --preview
```

The preview is at `http://127.0.0.1:8000/`. Without `--preview`, the command only builds. `--api-only` regenerates API sources without building the website.

## Review context

CI covers formatting, lockfile and schema consistency, supported Python versions, Windows imports, distribution installation, and Redis-backed Runtime tests on Linux. The current support matrix is in `.github/workflows/main.yml` and package metadata is in `pyproject.toml`. Docs publish from `main`; previewing a change is local.

Focused tests help explain a behavior change. Existing assertions, import boundaries, and supported installs remain relevant regardless of how a patch was written. A useful completion report distinguishes checks run from behavior inferred or left unverified.

A shared checkout may contain unrelated changes. Keeping those separate makes the resulting diff reviewable. [CONTRIBUTING.md](CONTRIBUTING.md) has more setup and contribution information.
