Persistence backends used only by the Team Runtime.

Agents never talk to a Store. Pass `store="memory"` (default) or a
Redis URL into [`Team`](/api/team-runtime#agentconnect-team-runtime-team). [`MemoryStore`](/api/team-store-memory#agentconnect-team-store-memory-memorystore) is process-local. [`RedisStore`](/api/team-store-redis#agentconnect-team-store-redis-redisstore)
keeps memberships, mailboxes, open Tickets, and Thread history across
a Runtime restart. Shared Redis does not make extra Runtime replicas
safe.

Custom backends subclass [`Store`](/api/team-store-base#agentconnect-team-store-base-store) and implement `apply` so a Message,
Ticket, Thread append, and Mailbox item commit together. [`StoreOp`](/api/team-store-ops#agentconnect-team-store-ops-storeop)
types ([`Insert`](/api/team-store-ops#agentconnect-team-store-ops-insert), [`Cas`](/api/team-store-ops#agentconnect-team-store-ops-cas), [`Put`](/api/team-store-ops#agentconnect-team-store-ops-put), …) are the batch language `apply` takes.

**Examples:**

Redis must already be reachable. This fragment runs inside an async
function:

```python
from agentconnect.team import Team

team = await Team(
    "content-squad",
    store="redis://127.0.0.1:6379/0",
).start()
team.persistence
await team.stop()
```
