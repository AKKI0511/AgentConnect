Atomic store operations used by Runtime transitions.

A transition builds a list of these operations and passes them to
`apply`. The backend applies every operation or none of them. Ordinary
Agent code never constructs these values.

**Examples:**

```python
from agentconnect.team.store import Insert, Store

result = await store.apply(
    [
        Insert("msg:abc", message),
        Insert("ticket:abc", ticket),
    ]
)
if not result.ok and result.reason == "exists":
    ...
```

## `ApplyResult`

```python
ApplyResult(ok: bool, reason: Optional[str] = None, op_index: Optional[int] = None)
```

Outcome of `apply`.

`ok` means every operation committed. When `ok` is False, the
store is unchanged. `reason` is `exists` (insert hit a live
key), `cas` (version mismatch or missing compare-and-set target),
`busy` (index cardinality cap), or `limit` (increment cap).

**Attributes:**

* `ok` (`bool`): True when every operation committed.

* `reason` (`Optional[str]`): Conflict kind when `ok` is False.

* `op_index` (`Optional[int]`): Index of the operation that conflicted, when known.

## `IndexAddIfCardBelow`

```python
IndexAddIfCardBelow(key: str, score: float, member: str, max_card: int)
```

Add `member` when the index has fewer than `max_card` members.

Updating an existing member's score always succeeds. A new member
past the cap fails the batch with `busy`.

**Attributes:**

* `key` (`str`): Index key.

* `score` (`float`): Sort score.

* `member` (`str`): Indexed member.

* `max_card` (`int`): Maximum distinct members allowed.
